## Numbered Findings List

### Group 1: Hard Gate (Priority: HIGH)

1. **R-02 (Copywriting)** — HIGH: Em dash (`—`) used as fallback placeholder text in `src/pages/DashboardPage.vue` (line 30), `src/pages/ActivityPage.vue` (line 50), and `src/pages/ActivityPage.vue` (line 110) instead of a standard hyphen, colon, or natural phrase.
2. **R-03 (Mobile Responsiveness)** — HIGH: Global stylesheet enforces `min-width: 720px` on `html, body, #app`, fixed-width tables (`.activity-table` min-width 900px, `.preview-table` min-width 780px), and sub-44px interactive tap targets (`.button--small`, `.icon-button`, `.health-pill` at 31–32px), causing horizontal clipping on narrow screens.
3. **R-25 (Color Contrast)** — HIGH: Multiple text and badge elements fail WCAG AA 4.5:1 contrast, including muted text `--text-faint` (`#8b8ea2` on `#ffffff` = 3.24:1), `.version-label` (`#686b82` on `#111326` = 3.51:1), warning badges (`#a86c15` on `#fff6df` = 4.04:1), tags (`#7055e8` on `#eeeaff` = 4.30:1), and `.eyebrow` in onboarding (`#7055e8` on `#251e51` = 3.00:1).
4. **R-27 (UI States)** — HIGH: `src/pages/ActivityPage.vue` and `src/components/PreviewModal.vue` lack in-panel error state views when asynchronous data queries or scan operations fail.
5. **R-32 (Keyboard Accessibility)** — HIGH: Preset selection radio buttons in `src/pages/OnboardingPage.vue` (`.preset-grid input`) use `opacity: 0` without a `:focus-visible` outline on the parent label, leaving keyboard users with no focus indicator.
6. **R-37 (Design Direction Required)** — HIGH: The project has no `DESIGN.md` or explicit brand direction, causing the application to fall into generic AI dark-purple SaaS defaults without declared dials.
7. **R-39 (Accessible Semantics & Interaction Affordances)** — HIGH: Base stylesheet lacks global `cursor: pointer` on interactive elements, hiding nav labels on mobile via `display: none` without `aria-label` removes accessible names for screen readers, and interactive elements (`.nav-item`, `.text-button`) lack `:active` states.

### Group 2: Purpose-Gate (Priority: MEDIUM)

8. **R-01 (Color & Gradients)** — MEDIUM: Unmotivated blue-purple gradients, radial orbs, and glow treatments appear on the sidebar, monitoring hero, onboarding banner, and primary buttons without documented brand purpose.
9. **R-04 (Icons)** — MEDIUM: A generic 4-point AI sparkle icon is used on the primary "Rapikan Sekarang" button in `src/App.vue` (line 132), and an arbitrary diagonal arrow `↗` is used for empty states in `src/pages/DashboardPage.vue` and `src/pages/ActivityPage.vue`.
10. **R-06 (Typography)** — MEDIUM: Uppercase category eyebrow labels with wide letter-spacing (`0.16em`) are repeated as default decoration above headings on every view (`OVERVIEW`, `AUTOMATION`, `AUDIT TRAIL`, `PREFERENCES`, `SETUP 1 MENIT`, `RULE BUILDER`, `SAFE MODE`).
11. **R-07 (Background Patterns)** — MEDIUM: A 22px technical grid overlay (`background-image: linear-gradient(...)`) is layered across the monitoring hero in `src/style.css` (line 152) as unmotivated aesthetic texture.
12. **R-08 (Button Arrows)** — MEDIUM: Purely decorative arrows (`→` and `←`) are appended to buttons and links in `src/pages/DashboardPage.vue` and `src/pages/OnboardingPage.vue`.
13. **R-09 (Badges & Eyebrows)** — MEDIUM: Redundant eyebrow pills parked directly above titles repeat information already stated in headings, combined with glowing status capsule badges (`.health-pill`).
14. **R-13 (Glow)** — MEDIUM: Glow and multi-layered box-shadow effects are applied across brand marks, buttons, pills, status indicators, and onboarding cards simultaneously without documented elevation hierarchy.
15. **R-14 (Feature Cards)** — MEDIUM: The dashboard overview uses 4 identically-sized stat cards in a rigid 4-column grid with identical icon-number-caption layouts, flattening visual hierarchy between primary and secondary metrics.
16. **R-19 (Animations)** — MEDIUM: Infinite radar pulse animation rings (`@keyframes pulse`) run continuously in the dashboard hero visual as aesthetic filler without a specific UX trigger.

### Group 3: Quality Locks (Priority: LOW)

17. **R-05 (Layout & Page Structure)** — LOW: Onboarding and dashboard adhere to classic AI templates (Hero + 4 uniform stat cards, 3-step numbered circular progress sequence 1-2-3).
18. **R-11 (Border Radius)** — LOW: The stylesheet defines more than 10 disparate border-radius values (6px, 7px, 8px, 9px, 10px, 11px, 12px, 13px, 14px, 15px, 17px, 18px, 20px, 24px, 999px) without an intentional design token system.
19. **R-20 (Visual Identity)** — LOW: The overall UI relies on generic AI developer-tool tropes (Linear-like dark sidebar, purple glowing primary buttons, tech grid backgrounds) lacking distinct character.
20. **R-21 (Dark Mode)** — LOW: The application forces a dark navy sidebar and dark hero blocks even in light mode, rather than fully honoring the light theme.
21. **R-29 (Color Palette)** — LOW: The interface employs 5 distinct functional accent colors alongside multiple dark navy and purple gradients, exceeding the recommended 2-3 core colors + 1 accent cap.
22. **R-31 (Every Decision Must Have a Reason)** — LOW: Visual decisions (color selection, animations, card grids, shadows) are undocumented and lack one-line justifications.
